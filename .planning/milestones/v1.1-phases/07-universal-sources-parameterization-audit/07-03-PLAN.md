<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP caller → mastodon_* `instance`/`tag` params | Untrusted host + tag select the outbound base and path |
| Mastodon instance → server | Response may be a 401/422 anonymous-denied lockdown or a disabled-trends 404/empty |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Information disclosure (SSRF) | mastodon_* getJson with user-supplied `instance` (e.g. 127.0.0.1 / 169.254.169.254) | high | mitigate | `getJson(url,{untrustedHost:true})` on every call (assertSafeUrl denylist + redirect re-validation); private-IP reject test (Task 3) |
| T-07-06 | Denial of service | Unbounded `limit` making envelope count mismatch / large fetch | low | mitigate | zod `max(40)` rejects >40 before fetch (D-08); limit-reject test (Task 3) |
| T-07-04 | Denial of service | Lockdown/HTML response parsed as JSON → crash | medium | mitigate | Content-type gate + 401/422 terminal handling → D-11 message (Task 1); 422 fixture test (Task 3) |
| T-07-02 | Tampering | Hardcoded instance host/handle creeps into mastodon server.js | medium | mitigate | Base is always the tool param (no host literal); enforced by the plan 07-04 SEC-02 audit |
| T-07-SC | Tampering | package installs | low | accept | Zero new dependencies (RESEARCH §Standard Stack) — no install surface |
| T-04-06 | Information disclosure | DNS-rebinding TOCTOU on guarded path | low | accept | Accepted residual (SEC-03) for a local single-user tool; not reopened |
</threat_model>
