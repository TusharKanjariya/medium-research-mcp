<objective>
Add a Stack Exchange high-view unanswered-question mining tool (`so_unanswered`) that
fetches the `/questions/no-answers` set for a required tag, ranks it client-side by
`view_count` descending (SE has no server-side view sort — `sort=views` is rejected,
Pitfall 2), and maps `view_count` into the contract `score` (TREND-02, D-07/D-08).
Throttle handling honors the API `backoff` field behaviorally and surfaces quota
exhaustion through the error path — the frozen `{source,query,count,results}` envelope
gains NO new field (OQ-1 resolved).

Purpose: a high-view zero-answer question is the purest unmet-need signal for a blog
topic; deliver it without breaking the output contract and without a self-inflicted SE
throttle ban.
Output: the so_unanswered tool, mapSeUnanswered + seThrottle helpers, three
hand-synthesized fixtures, and offline tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM/tool input (tag/site/limit) → fixed SE API URL | User input populates query-string params only (`tagged`, `site`, `pagesize`); the host is the module constant `SE`, never user-supplied. |
| SE quota state → tool behavior | The upstream throttle/quota signal can, if mishandled, cause a self-inflicted IP ban across ALL SE tools. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-31 | Denial of Service (self-inflicted) | SE quota exhaustion / backoff violation | medium | mitigate | Single-fetch window (`pagesize = min(limit*2, 100)`, no paging) so the common case never needs a follow-up; `seThrottle` honors `backoff` (sleep before any follow-up) and throws a clear set-STACKEXCHANGE_KEY error at `quota_remaining === 0`; 15-min TTL cache dampens repeat calls; strict no-4xx-retry unchanged. |
| T-05-32 | Tampering | so_unanswered URL construction (tag/site injection) | low | mitigate | All user input goes through `seUrl` → `URLSearchParams` (encodes values); fixed host constant — no user-supplied host, no SSRF surface. The API key rides the authed URL only and never the cache key or error text (WR-01, reused). |
| T-05-SC | Tampering | npm/dependency supply chain | low | accept | Zero new runtime dependencies (keyless GET through the existing client); no install step — Package Legitimacy Gate N/A. |

No new untrusted-host surface — fixed-host API tool. No high-severity threats; ASVS L1
block-on-high is satisfied.
</threat_model>
