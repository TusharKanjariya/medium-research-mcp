<objective>
Extend the v1.0 SSRF guard — today only on the getText/RSS path — to a guarded JSON
path so any getJson request whose host comes from untrusted tool input is validated
by the same assertSafeUrl denylist + per-hop redirect re-validation. This is SEC-01,
the single gating dependency for the rest of v1.1 (Phase 7's Discourse/Mastodon
servers and Lemmy's parameterization all ride this path). Then move Lemmy's three
instance-parameterized getJson calls onto the guarded path.

Purpose: close the SSRF gap where a user/LLM-supplied instance host could reach an
internal/metadata service through getJson (Pitfall 3), without forking a second guard
(D-02) and without touching fixed-host callers (D-01).
Output: an opt-in untrustedHost option on getJson (content-type gate + creds-in-URL
reject included), the guarded-JSON SSRF test suite, and Lemmy on the guarded path.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM/tool input → getJson host | An instance host supplied via tool input (Lemmy now; Discourse/Mastodon in Phase 7) crosses into an outbound HTTP request on the shared chokepoint. |
| Redirect Location → next hop | A 3xx Location returned by an upstream can point the next hop at an internal address. |
| operator env (LEMMY_INSTANCE) → getJson host | An operator-set instance host is now also validated (belt-and-suspenders, Pitfall 5). |
