<objective>
Build the generic RSS/Atom fetcher server (SRC-09) and its offline test suite,
including the documented subreddit `.rss` (D-06) and YouTube channel/playlist
(D-15, YT-01) recipes. A single `rss_fetch(url, limit?)` list tool (D-04 — no
`*_get`/`*_search`) ingests any RSS 2.0 or Atom 1.0 feed and maps each entry onto
the contract item schema with `type: "article"` and `score`/`num_comments` BOTH
null (D-05, ARCHITECTURE §5).

All HTTP + SSRF safety already lives in the shared `getText` (04-01) and the parser
was installed in 04-02, so this server is pure field-mapping + parsing — exactly the
"mechanical copy of the pattern" the suite is built on.

Purpose: The biggest coverage-per-line multiplier — one tool unlocks arbitrary
newsletters, dev blogs, read-only subreddits, and YouTube channels/playlists.
Output: `servers/rss/server.js` (rss_fetch + parseFeed + normalizeFeed + mapRssItem
+ mapAtomEntry), manifest.json (documents both recipes), test/rss.test.js, and four
real captured fixtures. YT-01 is satisfied here by the YouTube recipe + its fixture
test + the documented recipe (no Python, no OCR — D-13/D-14).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tool input → rss_fetch → getText | The feed URL is untrusted; SSRF validation is INHERITED from getText (04-01, T-04-01..08) — the server adds no new outbound-host surface. |
| feed XML → parseFeed | Untrusted third-party XML is parsed into objects the server maps. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-09 | Denial of Service | XML entity expansion / "billion laughs" in a malicious feed | medium | mitigate | fast-xml-parser does not resolve external/DTD entities by default; `limit` caps emitted items; getText's 10s timeout bounds fetch time. |
| T-04-10 | Tampering / Info Disclosure | Non-feed HTML (200) dereferenced as a feed | medium | mitigate | normalizeFeed root-detection guard throws a clear error (Pitfall 6) rather than emitting a junk item. |
| T-04-11 | Information Disclosure | SSRF via the feed URL / redirect | high | transfer | Fully handled by getText/assertSafeUrl (04-01); rss_fetch performs no direct fetch and cannot bypass it (Universal Server Bar). |
| T-04-12 | Tampering | Stored XSS-ish HTML surfaced in `text` | low | mitigate | `stripHtml` (via normalizeItem) removes tags/scripts before output (OUT-03). |
</threat_model>
