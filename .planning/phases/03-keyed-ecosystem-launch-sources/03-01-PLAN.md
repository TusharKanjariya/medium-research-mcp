<objective>
Deliver the GitHub source server (SRC-06) covering two entity types on the uniform
contract — trending repos (stars->score) and issues for pain-point mining
(reactions->score, comments->num_comments) — with an optional PAT that degrades to
anonymous access. Before the server can return anything, extend the shared `TYPE`
enum so `issue` (and, for 03-02, `package`/`launch`) pass SDK output validation.

This is plan 03-01 of the two-plan split (D-11): GitHub here, Libraries.io + Product
Hunt in 03-02.

Purpose: GitHub carries the phase's highest-value blog-topic signal (high-reaction
open issues = "what developers are frustrated by") and exercises the optional-PAT
credential path. The `TYPE` extension is a hard prerequisite for the whole phase.
Output: extended `TYPE` enum; `servers/github/server.js` (3 tools) + manifest;
`test/github.test.js` + fixtures.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Desktop tool input -> server handler | Untrusted query/language/labels/owner/repo/number cross here |
| server -> api.github.com | Outbound request to a FIXED module-constant host |
| GITHUB_TOKEN env -> Authorization header | Optional credential enters the request via githubHeaders() only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | githubHeaders() PAT | low | mitigate | PAT rides only in the Authorization header (never in URL/cacheKey); redactUrl strips query from error text; no credential is logged |
| T-03-02 | Tampering/Info Disclosure (SSRF) | outbound host selection | medium | mitigate | GH host is a module constant; tool input fills only the q string and encoded path segments — never the host (same invariant as lemmyInstance). language/labels/repo are Search qualifiers sent to the fixed host, not host selectors |
| T-03-03 | Tampering | passthrough qualifiers in q | low | mitigate | encodeURIComponent on the composed q and on owner/repo/number path segments; GitHub validates qualifiers server-side; is:issue filters out PRs (Pitfall 5) |
| T-03-SC | Tampering | npm installs | low | accept | No package installs this phase (RESEARCH Package Legitimacy Audit — zero new deps); no supply-chain surface to gate |
</threat_model>
