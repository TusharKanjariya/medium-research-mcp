<objective>
Make the rss server writer-aware: add `rss_author_posts(author, query?, published_before?)`
(ABLOG-01/02) and `rss_tag_posts(tag)` (ABLOG-04), reusing the shipped
`getText -> parseFeed -> normalizeFeed -> slice -> buildListEnvelope -> toolResult`
pipeline. The author is a single smart parameter whose shape selects the platform
(D-02/D-03); coverage windows are honest in the descriptions (D-05); paywall/preview
truncation surfaces as the literal `preview-only` tag (D-06/D-07) with the frozen
contract intact.

Purpose: the milestone's headline capability — read a chosen author's Medium /
Substack / raw-feed posts in the normalized contract, honestly windowed.
Output: two new registered tools + two exported pure helpers + offline fixtures/tests;
the `rss_fetch` SINGLE-TOOL note updated so it no longer claims the server exposes only `rss_fetch`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tool input `author`/`tag` -> resolveAuthorFeed -> getText | An LLM-supplied string is turned into an outbound feed URL. The raw-URL branch and the derived Medium/Substack URLs all fetch through `getText`, which runs `assertSafeUrl` (scheme allowlist + private-range denylist + per-hop redirect re-validation) unconditionally. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-03 | Spoofing / SSRF footgun | resolveAuthorFeed host inference | medium | mitigate | Ambiguous bare tokens THROW — never synthesize/guess a host (D-03). Only `@handle` (fixed medium.com host), `*.substack.com` (fixed substack.com host), or an explicit `http(s)://` URL resolve; the explicit URL still rides `getText`'s `assertSafeUrl`. Asserted by the ambiguous-reject test. |
| T-06-04 | Tampering (SSRF) | raw-feed-URL branch -> getText | high | mitigate | Raw URLs are NOT specially trusted — they pass through `getText`'s existing unconditional SSRF guard (assertSafeUrl on the initial host + every redirect hop). No new guard, no bypass introduced. |
| T-06-05 | Information disclosure | contract text vs preview flag | low | mitigate | Preview state rides `tags[]` (literal `preview-only`), never a new field and never inline text mutation — the consuming skill can still cite `text` verbatim; contract stays frozen. |
| T-06-SC | Tampering | npm/pip/cargo installs | high | accept | No package installs — zero new runtime dependencies this phase. No `[ASSUMED]`/`[SUS]` packages to gate. |
</threat_model>
